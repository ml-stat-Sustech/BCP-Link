# BCP-Link Configuration Guide

The canonical configuration is [`searcherkit.yaml`](searcherkit.yaml). This guide separates deployment-specific settings from benchmark settings so that models can be served in different environments without changing the BCP-Link evaluation condition.

As a general rule, paths, endpoint addresses, credentials, concurrency, output locations, and the evaluated model may change. Retrieval behavior, corpus fields, prompts, tool limits, and benchmark data fields should remain fixed.

## Settings that may be changed

### LLM client

| Setting | How it may be changed |
| --- | --- |
| `model` | Set this to the evaluated model identifier accepted by the inference endpoint. It may be a served model name or a model path. |
| `api_key` | Set this to the inference endpoint credential. Local servers commonly accept a placeholder such as `a`. |
| `base_url` | Point this to one or more OpenAI-compatible inference endpoints. Adding replicas changes throughput, not the benchmark condition. |
| `concurrency_limit` | Adjust this for available inference capacity. It should not change the contents of a single trajectory. |
| `extra_client_kwargs` | Use only when required for compatibility with the evaluated model or serving framework. Do not use it to change the benchmark sampling policy. |

The `upstream` parser is the standard choice for endpoints that return OpenAI-compatible parsed tool calls. A model-specific parser may be used when required to interpret that model's native tool-call format, but it should only perform format conversion rather than change prompts or reasoning behavior.

### Model context length

| Setting | How it may be changed |
| --- | --- |
| `max_tokens` under the agent | Set this to the effective context length actually supported by the served model. Models may use their native maximum context length. |

The `max_tokens` inside `default_kwargs` is different: it limits the number of new tokens generated by each individual LLM request. It is part of the standard generation policy and should normally remain fixed.

### Elasticsearch and embedding services

| Setting | How it may be changed |
| --- | --- |
| `hosts` | Point this to the local or remote Elasticsearch service. |
| `index` | The index name may differ, but its corpus contents, schema, and embeddings must match the released BCP-Link index. |
| `es_max_concurrency` | Adjust this for Elasticsearch capacity. |
| `embedding_model` | The path or served identifier may change, but the embedding weights must remain Qwen3-Embedding-8B for comparable results. |
| `embedding_api_key` | Set this to the embedding endpoint credential. |
| `embedding_base_url` | Point this to the OpenAI-compatible embedding endpoint. |
| `embedding_max_concurrency` | Adjust this for embedding-service capacity. |

### Dataset and output

| Setting | How it may be changed |
| --- | --- |
| `source` under `dataloader` | Set this to the local decrypted benchmark JSONL path. The file contents must match the released benchmark. |
| `max_items` | Use a small value such as `1` for a smoke test. It must be `null` for the complete benchmark. |
| `max_concurrency` | Adjust the number of benchmark samples processed concurrently for available serving capacity. |
| `output_path` | Use any output directory. Use a separate directory for each model and benchmark condition. |
| `overwrite_output` | Choose whether existing histories may be replaced. Keeping it `false` is safer for normal runs. |
| `enabled`, `dir`, `resume`, `filename` under `checkpoint` | These control persistence and resume behavior and may be adapted to the execution environment. They do not change a successfully generated trajectory. |
| `logging` | Log paths, trace paths, formats, and levels may be changed freely. |

## Standard settings that should remain fixed

### Canonical values

The following values define the standard BCP-Link evaluation condition.

#### Generation, parser, and retry

```yaml
parser:
  type: upstream

default_kwargs:
  temperature: 1.0
  top_p: 1.0
  max_tokens: 8192

task_retry_policy:
  max_tries: 3

llm_retry_config:
  max_tries: 5
  exceptions:
    - pkg://searcherkit.llm.parsers:ParsingError

tool_retry_config:
  max_tries: 5
  exceptions:
    - pkg://searcherkit.common.errors:RecoverableError
```

#### Corpus and retrieval

```yaml
search_fields: ["title", "text"]
title_field: title
text_field: text
url_field: url
fetch_field: url

highlight: true
snippet_chars: 1024
vector_search_mode: hybrid
vector_field: text_vector
vector_num_candidates: 50

embedding_model: Qwen3-Embedding-8B
embedding_prefix: |
  Instruct: Given a web search query, retrieve relevant passages that answer the query
  Query:
```

The path or served name used for `embedding_model` may differ, but it must resolve to the same Qwen3-Embedding-8B weights.

#### Search tool

```yaml
type: search
name: search
description: Search for more information.
inputSchema:
  type: object
  properties:
    query:
      type: string
  required:
    - query
  additionalProperties: false
source:
  - elasticsearch
default_top_k: 5
summarizer: null
raise_argument_validation_error: false
```

#### Visit tool

```yaml
type: visit
name: visit
description: Fetch the full local document. Pass a URL found in a snippet/document.
inputSchema:
  type: object
  properties:
    document_id:
      type: string
    goal:
      type: string
  required:
    - document_id
  additionalProperties: false
source:
  - elasticsearch
response_char_limit: 40000
summarizer: null
raise_argument_validation_error: false
```

`summarizer: null` documents the effective canonical behavior. The YAML may omit this key because no summarizer is configured by default.

#### Prompts and limits

```yaml
system_prompt: |
  You are a helpful AI assistant that can search for information to answer questions accurately.

  When answering questions:
  1. Use the available search tools to find relevant and reliable information.
  2. Synthesize information from multiple sources when needed.
  3. Provide accurate and comprehensive answers based on your search results.
  4. Do not use Chinese in your responses, keep using English only.
  5. Do not search the same query multiple times.
  6. Use visit with URL values copied from search results. If a snippet or visited document contains a clearly relevant URL, you may pass that URL to visit.
  7. Do not change URLs in search results or visited documents.
  8. Do not call tools inside <think></think>.
  9. Always put your final answer in \boxed{} format
  For example:
  - If the answer is "American", write: \boxed{American}
  - If the answer is "yes", write: \boxed{yes}
  - If the answer is a year like "1985", write: \boxed{1985}

query_prompt: "<question>{query}</question>"
max_turn: 50
max_turn_prompt: |
  You have now reached the maximum tool call turns you can handle. You should stop making tool calls and, based on all the information above, think again and provide what you consider the most likely answer in the following format:
  \boxed{your answer}
max_tokens_prompt: |
  You have now reached the maximum context length you can handle. You should stop making tool calls and, based on all the information above, think again and provide what you consider the most likely answer in the following format:
  \boxed{your answer}
max_tokens_prompt_margin: 8192
```

The agent-level `max_tokens` is not listed here because it should match the effective context length of the evaluated model.

#### Benchmark data fields

```yaml
input_key: query
answer_key: answer
extra_keys:
  - query_id
  - evidence_docs
max_items: null
```

### Why these values are fixed

#### Generation and parser

`temperature`, `top_p`, and the per-request `max_tokens` affect sampling and response length. The parser controls how tool calls are interpreted. A model-specific parser is acceptable only when required for format compatibility and should not change the prompts or agent behavior.

The retry policies determine which transient failures are retried and how many attempts are allowed. Changing them can alter the number of completed benchmark samples.

#### Corpus fields

`search_fields` controls BM25 retrieval. `text_field` controls highlighting, snippets, returned document text, and the full document returned by `visit`. The canonical BCP-Link condition exposes the link-augmented `text` field.

For the separate BCP baseline, the only allowed corpus-condition change is:

```yaml
search_fields: ["title", "text_raw"]
text_field: text_raw
```

The provided `run_inference.sh` applies both values through one variable. Keep `CONTENT_FIELD=text` for BCP-Link and use `CONTENT_FIELD=text_raw` for BCP.

#### Retrieval

Hybrid mode, candidate count, embedding weights, vector field, query prefix, highlighting, and snippet length determine which evidence is exposed to the model. Changing any of them creates a different retrieval condition.

`snippet_chars` is measured in characters, not words or tokens. `vector_num_candidates` is the dense candidate pool before the final results are returned.

#### Search and visit tools

`default_top_k` is the number of search results used when the model does not provide `top_k`. `response_char_limit` is the maximum `visit` response length in characters. The canonical configuration does not use a search or visit summarizer.

Tool names, descriptions, input schemas, and source bindings are visible to the model and must remain unchanged.

#### Prompts and limits

The system and query prompts define browsing behavior and the required `\boxed{}` final-answer format. `max_turn`, the final-answer reminder prompts, and `max_tokens_prompt_margin` determine when browsing stops and the model must answer.

#### Benchmark data fields

The full benchmark requires `max_items: null`. A non-null value is only for smoke tests. Keep `query_id` and `evidence_docs`; they are required to associate samples with the benchmark and calculate BCP-Link evidence recall.

## Evaluation denominator

`benchmark_total` is not part of the generation YAML. Supply it to the evaluator with `BENCHMARK_TOTAL` or `--benchmark-total`, or let the evaluator read `total` from the generation `summary.json`.

The official accuracy definition is always:

```text
accuracy = correct / benchmark_total
```

Generation failures, missing histories, judge failures, and invalid judge results remain in the denominator and count as incorrect.
